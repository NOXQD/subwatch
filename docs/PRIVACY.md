# Приватность и безопасность

Subwatch читает почту и банковские выписки, поэтому исходил из простого
правила: брать только то, без чего не обойтись, и хранить только у вас.

## Что хранится

База: `~/.local/share/subwatch/subwatch.db`, права `600`, каталог — `700`.

| Таблица | Что внутри |
|---|---|
| подписки | сервис, сумма, валюта, период, даты, категория, теги, статус, откуда узнали, адрес отправителя |
| списания | дата и сумма каждого списания, ссылка на письмо — хэшем |
| обработанные письма | хэш идентификатора письма и итог разбора |
| операции из выписок | дата, сумма, валюта, нормализованное имя получателя |
| правила | ваши решения из очереди проверки |
| напоминания, события | когда о чём напоминали, что уже сообщали |
| курсы валют | последние загруженные курсы |
| журнал AI | время, провайдер, модель, размер и хэш запроса |

Тексты писем не сохраняются. Если включить
`extraction.store_snippets`, рядом с подпиской ляжет короткий фрагмент
(`snippet_chars` символов) — уже очищенный от адресов, номеров карт и
телефонов. Номера карт, остатки, назначения переводов из выписок не
сохраняются.

Кроме базы: `config.toml` (без секретов), календарь `subwatch.ics`, кэш
модуля панели, список *имён* записей в keyring
(`~/.local/state/subwatch/secrets.json`) — чтобы `purge` знал, что
удалять.

```bash
subwatch privacy               # всё это одним списком
subwatch privacy --payloads    # плюс тексты запросов к AI, если сохранялись
```

## Секреты

Токен Gmail, пароли IMAP, ключ облачной модели и ключ шифрования базы
хранятся только в системном keyring (gnome-keyring или KWallet через
Secret Service). В файлы, журнал и git они не попадают. Если keyring
недоступен или это «заглушка» без шифрования, Subwatch откажется
сохранять секрет и скажет, что поставить; `subwatch doctor` проверяет это.

## Почта только на чтение

- Gmail: разрешение `gmail.readonly`, другого Subwatch не просит.
- IMAP: папки открываются через `EXAMINE`, письма читаются `BODY.PEEK`,
  команды `STORE`, `COPY`, `EXPUNGE`, `APPEND` не отправляются. Это
  проверяется тестом на тестовом IMAP-сервере.

## Шифрование базы

```toml
[storage]
encrypt = true
```

На диске остаётся только `subwatch.db.enc` (AES-256-GCM), ключ — в
keyring. Пока программа работает, SQLite открывает расшифрованную копию в
`$XDG_RUNTIME_DIR` — это память, а не диск, она доступна только вам и
исчезает при выходе из сессии. После каждой записи копия снова
шифруется. Если выключить опцию, база один раз расшифруется обратно.

Без ключа зашифрованную базу не открыть — если keyring потерян, данные
тоже.

## Что уходит в сеть

- Gmail API и ваш IMAP-сервер — за письмами.
- Нацбанк РК, ЦБ РФ, open.er-api.com или frankfurter.app — за курсами
  валют, раз в `cache_ttl_hours` (или никуда при `rates_source = "manual"`).
- AI-модель — только если вы её включили, см. [AI.md](AI.md).

Больше никуда: ни телеметрии, ни проверки обновлений.

## Удалить всё

```bash
subwatch auth revoke gmail     # отозвать доступ у Google и удалить токен
subwatch auth revoke all       # плюс пароли IMAP и ключ AI
subwatch purge                 # база, календарь, кэш, токены; настройки остаются
subwatch purge --all           # и настройки тоже
./uninstall.sh --purge         # всё перечисленное и сама программа
```

Пароль приложения IMAP после `revoke` стоит отозвать и в настройках
почты — у IMAP нет способа сделать это за вас.
