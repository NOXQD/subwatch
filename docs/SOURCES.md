# Источники

Подписки появляются из четырёх мест: Gmail, любая почта по IMAP,
банковские выписки и ручной ввод. Ещё можно написать свой источник —
см. [EXTENDING.md](EXTENDING.md).

## Gmail

```bash
subwatch auth gmail
```

Мастер проведёт по шагам. Коротко, что происходит:

1. Вы создаёте свой проект в Google Cloud и включаете в нём Gmail API.
   Общего «приложения Subwatch» нет — доступ получает только ваш проект.
2. На экране согласия добавляете одно разрешение —
   `https://www.googleapis.com/auth/gmail.readonly`. Писать, удалять и
   помечать письма Subwatch не может.
3. **Переводите проект в режим «In production».** Пока проект в режиме
   Testing, Google выдаёт токен на 7 дней, и через неделю сканирование
   перестанет работать. Для личного проекта проверка Google не нужна; при
   входе появится экран «Google hasn't verified this app» — это ожидаемо,
   нажмите «Advanced» → «Go to … (unsafe)».
4. Создаёте OAuth-клиент типа «Desktop app», скачиваете JSON и указываете
   путь к нему. Открывается браузер, вы входите, токен уходит в keyring.
   JSON после этого можно удалить — мастер предложит.

Если вход прошёл, а через неделю `subwatch doctor --online` пишет, что
токен не работает, — проект остался в Testing. Переведите его и пройдите
`subwatch auth gmail` ещё раз.

Как сканируется Gmail:

- первый раз — поиск по запросу, где есть слова «чек», «подписка»,
  «receipt», «жазылым» и т. п. и адреса известных сервисов, за
  `scan.months_back` месяцев;
- дальше — через History API от сохранённого `historyId`: Google отдаёт
  только новые письма. У них сначала скачиваются заголовки, и только если
  письмо похоже на нужное — тело (без вложений);
- если `historyId` устарел (Google хранит историю около недели), поиск по
  дате последнего сканирования;
- запросы ограничены `sources.gmail.rate_limit` в секунду, ошибки сети и
  429/5xx повторяются с паузой.

Отозвать доступ: `subwatch auth revoke gmail` — токен отзывается у Google и
удаляется из keyring.

## IMAP

Подходит любой почтовый сервис: Яндекс, Mail.ru, Outlook, Fastmail,
собственный сервер. Нужен **пароль приложения**, а не основной пароль —
его создают в настройках безопасности почты.

```bash
subwatch auth imap --name yandex --host imap.yandex.ru --user me@yandex.ru
```

Команда спросит пароль, проверит вход, покажет, какие папки есть на
сервере, сохранит пароль в keyring, а адрес и папки — в config.toml.
Учётных записей может быть сколько угодно, у каждой свой список папок:

```toml
[[sources.imap.accounts]]
name = "yandex"
host = "imap.yandex.ru"
username = "me@yandex.ru"
folders = ["INBOX", "Чеки"]
```

Что гарантируется:

- папки открываются командой `EXAMINE` (только чтение), письма читаются
  через `BODY.PEEK`, флаг «прочитано» не ставится, ничего не удаляется и
  не перемещается;
- сначала скачиваются только заголовки (`From`, `Subject`, `Date`), тело —
  только у подходящих писем и не больше `fetch_max_bytes`;
- запоминается последний UID каждой папки вместе с `UIDVALIDITY`.
  Если сервер сменил `UIDVALIDITY`, папка перечитывается по дате, а уже
  разобранные письма узнаются и повторно не учитываются.

Популярные серверы: Яндекс — `imap.yandex.ru`, Mail.ru — `imap.mail.ru`,
Gmail по IMAP — `imap.gmail.com`, Outlook — `outlook.office365.com`,
Fastmail — `imap.fastmail.com`.

## Выписки

```bash
subwatch import ~/Загрузки/выписка.pdf
subwatch import tbank.csv kaspi.pdf          # несколько файлов сразу
subwatch banks                                # какие шаблоны есть
```

Поддерживаются CSV и PDF. Формат узнаётся по заголовкам колонок (CSV) или
по тексту в файле (PDF). Встроенные шаблоны:

| Шаблон | Что это |
|---|---|
| `kaspi_gold` | PDF-выписка Kaspi Gold |
| `tbank` | CSV-выгрузка операций Т-Банка (cp1251) |
| `generic_ru` | таблица «Дата; Сумма; Описание» |
| `generic_en` | таблица «Date, Amount, Description» (Revolut, Wise и похожие) |

Шаблоны Kaspi и Т-Банка сделаны по публичным примерам выгрузок; если банк
поменяет формат, шаблон придётся поправить — это обычный TOML-файл.

Если формат не узнан, команда в терминале спросит, какая колонка за что
отвечает. То же самое можно сказать сразу и сохранить как шаблон:

```bash
subwatch import bank.csv --map "date=Дата операции,amount=Сумма,description=Получатель" \
    --date-format "%d.%m.%Y" --save-template mybank
subwatch import next-month.csv --bank mybank
```

Свои шаблоны лежат в `~/.config/subwatch/banks/*.toml`, пример с
комментариями — `contrib/banks/example.toml`.

Если выписки регулярно скачиваются в одну папку, укажите её:

```toml
[sources.statements]
inbox_dir = "~/Загрузки/выписки"
```

Тогда новые файлы оттуда импортируются при каждом сканировании, уже
импортированные (по хэшу содержимого) пропускаются.

Как ищутся подписки: списания группируются по нормализованному получателю
(`NETFLIX.COM*123` → Netflix), и для каждого периода из
`recurrence.periods` (7, 30, 90, 365 дней) ищется самая длинная цепочка
списаний с почти одинаковыми интервалами и суммами. Одно изменение суммы
внутри цепочки допускается — это подорожание, оно будет отмечено. Для
надёжного поиска нужны выписки хотя бы за три месяца (для годовых
подписок — за два года).

Из выписок хранится только то, что нужно для поиска повторов: дата,
сумма, валюта и нормализованное имя получателя. Номера карт, остатки и
прочие строки не сохраняются. Операции старше
`keep_transactions_days` удаляются.

## Вручную

```bash
subwatch add Netflix --amount "3 990 ₸" --next "1 ноября"
subwatch add "Облако работы" --amount 12 --currency USD --period 1y --category cloud --tag работа
```

Если сервис есть в справочнике, категория, период по умолчанию и ссылка
на отмену подставятся сами. Без параметров `add` спросит всё в терминале.
В TUI то же самое — клавиша `a`.

## Очередь проверки

Находки с уверенностью от `extraction.review_threshold` до
`extraction.auto_accept` не попадают в список сразу, а ждут решения:

```bash
subwatch review             # по одной, с вопросом д/н
subwatch review confirm 12
subwatch review reject Tasklane
```

В TUI — вкладка «Проверка», клавиши `y` и `n`. Подтверждение запоминается
правилом «принимать сразу», отказ — правилом «не подписка» (и, если письмо
пришло не от общего почтового домена, «игнорировать отправителя»).
Несколько писем об одном сервисе повышают уверенность, и находка может
перейти в список сама. Правила: `subwatch rules list`, удалить —
`subwatch rules remove НОМЕР`.
