# Решения

Журнал решений, которые пришлось принимать по ходу. Формат простой: что решил и
почему. Новые записи — внизу.

## 1. Интеграция под Omarchy 4, а не 3.x

В ТЗ упомянуты Waybar, Walker, mako и `~/.config/hypr/subwatch.conf` через
`source`. На целевой системе Omarchy 4.0.6, где всё это заменено одной
Quickshell-оболочкой, а Hyprland настраивается на Lua (детали в
docs/ENVIRONMENT.md). Делать интеграцию под отсутствующие программы
бессмысленно, поэтому:

- **Панель.** `subwatch bar` печатает JSON в формате Waybar. Его понимают и
  модуль `type: command` панели Omarchy, и `custom/*` в Waybar. Установщик
  добавляет модуль в `~/.config/omarchy/shell.json`; если найден Waybar —
  предлагает сниппет из `contrib/waybar/` (и умеет вставить его сам с бэкапом).
- **Меню.** Пункты добавляются в `~/.config/omarchy/extensions/omarchy-menu.jsonc`.
  Если в системе есть Walker (Omarchy 3.x), дополнительно кладётся меню
  Elephant в `~/.config/elephant/menus/`. На этой машине Walker нет, поэтому
  вариант для Elephant проверен только на уровне генерации файла.
- **Hyprland.** Бинды пишутся в `~/.config/hypr/subwatch.lua`, а в
  `hyprland.lua` добавляется блок с `require("hypr.subwatch")` под проверкой
  `package.searchpath`, чтобы удаление файла не ломало конфиг. Для старого
  `hyprland.conf` поддержан вариант с `subwatch.conf` и `source = ...`.
- **Уведомления.** См. п. 2.

## 2. Действия в уведомлениях

Демон Omarchy поддерживает `actions` формально, но кнопок не рисует и по клику
вызывает только `default`. Зато у него есть хинт `omarchy-exec-argv`. Поэтому:

- бэкенд `omarchy`: уведомление через `omarchy-notification-send --exec`, клик
  открывает `subwatch notify-action <id>` — меню из трёх пунктов (Оставить /
  Отменить / Отложить) через `omarchy-menu-select`;
- бэкенд `notify-send` (mako, dunst, swaync): обычные кнопки `-A keep=...`,
  отдельный фоновый процесс ждёт ответа;
- `auto` выбирает по `GetServerInformation`.

## 3. LiteLLM — необязательная зависимость

LiteLLM ставится на Python 3.14, но тянет ~60 пакетов и ~250 МБ (tokenizers,
tiktoken, aiohttp, openai, jinja2...). Для программы, которая хранит токены от
почты, такая поверхность атаки по умолчанию не оправдана, тем более что AI-слой
выключен по умолчанию. Решение:

- LiteLLM в группе `[ai]` (`uv tool install 'subwatch[ai]'` или
  `./install.sh --with-ai`);
- без него работают встроенные клиенты на `urllib`: Ollama (`/api/chat`) и любой
  OpenAI-совместимый API (OpenAI, OpenRouter, Groq, LM Studio, vLLM...);
- если LiteLLM установлен и провайдер не из этих двух, используется он.

## 4. Шифрование базы без SQLCipher

SQLCipher в системе нет, а `sqlcipher3` пришлось бы собирать. Вместо этого
опция `storage.encrypt`: на диске лежит `subwatch.db.enc` (AES-256-GCM, ключ в
keyring), рабочая копия расшифровывается в `$XDG_RUNTIME_DIR/subwatch/` (tmpfs,
права 600, исчезает при выходе из сессии) и зашифровывается обратно после
записи. Доступ к файлам синхронизирован через `flock`.

## 5. uv на чистой системе

uv в Omarchy не предустановлен. `install.sh` пробует по очереди: уже
установленный uv → `sudo pacman -S --needed uv` (если есть терминал) →
официальный standalone-установщик в `~/.local/bin` (без правки rc-файлов).
Сам Subwatch ставится через `uv tool install`, в изолированное окружение.

## 6. Валюта по умолчанию — тенге

В ТЗ примеры сумм в тенге («1 299,00 ₸»), язык писем включает казахский.
Поэтому `currency.base = "KZT"`, а источник курсов в режиме `auto` для
тенге — Нацбанк РК. Для рубля автоматически выбирается ЦБ РФ, для
остальных валют — open.er-api.com (без ключа, есть тенге и рубль; у ЕЦБ
их нет).

## 7. Свой каталог строк вместо gettext

Каталоги — TOML (`resources/i18n/ru.toml`, `en.toml`): плоские ключи,
плюральные формы таблицей `one/few/many/other`, правило плюрализации
задаётся в самом каталоге (`meta.plural`). Новый язык — один файл в
`~/.config/subwatch/i18n/`, без компиляции `.mo`. Русский — эталон и
запасной вариант для недостающих строк.

typer (0.27) встраивает click и рисует справку сам; его английские
заголовки и сообщения об ошибках переводятся слоем `cli/chrome.py`:
константы подменяются строками каталога, сообщения click узнаются по
шаблону. Встроенные опции typer для автодополнения отключены — вместо
них команда `subwatch completion`.

Комментарии в стандартном `config.toml` — документация, а не строки
интерфейса, поэтому шаблон один, на русском
(`resources/config.default.toml`). Если появится
`config.default.<язык>.toml`, он будет использоваться для этого языка.

## 8. Приоритет правил напоминаний

«По сервису > по сумме > по категории», при равенстве — первое в файле.
Правила не складываются: действует одно, самое конкретное, а недостающие
в нём поля берутся из `[reminders]`. Так проще предсказать результат, чем
при слиянии нескольких правил.

## 9. Отмена письмом отменяет сервис, а не запись

Одна подписка может жить в двух записях (чек в долларах из письма и
списание в тенге из выписки). Письмо об отмене называет сервис, поэтому
отменяются все его живые записи. Вернуть подписку может только уверенная
находка списания после даты отмены — сомнительная не воскрешает.

## 10. Календарь — отдельными событиями, а не RRULE

Подписка «каждое 31-е» в коротких месяцах списывается 28–30-го;
`RRULE:BYMONTHDAY=31` такие месяцы просто пропускает. Поэтому в `.ics`
каждое списание — отдельное событие на `export.ics_months_ahead` месяцев
вперёд, с устойчивым UID. Файл перезаписывается после каждого изменения,
на него можно подписаться как на локальный календарь.

## 11. Справочник сервисов: «общие» и «зонтичные» записи

С одного домена приходят чеки разных сервисов (apple.com: iCloud+, Apple
Music, Apple TV+). Такие записи помечены `shared`: для них мало совпадения
отправителя, нужно упоминание сервиса в тексте. Записи `generic` (Apple,
Google Play, Microsoft, Яндекс) используются, только если ничего
конкретнее не нашлось.

## 12. Пороги уверенности

Оценка складывается из признаков: известный отправитель (+0.35), слова о
подписке в теме (+0.2), найденная сумма (+0.2), явный период (+0.1),
следующая дата (+0.05), признаки чека/продления/отмены (+0.1, у отмены
+0.2); слова про заказ и доставку дают −0.3. С порогами 0.8 и 0.45 чеки
известных сервисов принимаются сразу, а незнакомые сервисы и платежи,
пришедшие от банка, а не от сервиса, идут в очередь проверки. Повторное
письмо о том же сервисе добавляет 0.1. AI сам по себе даёт не больше 0.75.

## 13. Что никогда не уходит в AI

Демо показало, что письмо с кодом подтверждения формально «похоже на
подписку» (упомянут Яндекс) и попадало бы в модель вместе с кодом. Теперь
письма с кодами, сбросом пароля и уведомлениями о входе модели не
отдаются вообще, а короткие числа после слов «код»/«code» маскируются при
любой очистке.

## 14. Категории в конфиге — полный список

Если пользователь описал категории в `config.toml`, это и есть весь
список; стандартные с ним не сливаются. Иначе удалить ненужную категорию
было бы нельзя. Стандартный `config.toml` содержит все семь категорий, так
что из коробки они есть.

## 15. Модуль панели отвечает из кэша

Панель опрашивает `subwatch bar` по таймеру. Ответ кладётся в
`~/.cache/subwatch/bar.json` с отметкой о времени изменения базы, конфига
и текущей датой; пока они те же, `__main__` отдаёт кэш, не импортируя
pydantic, typer и SQLite.
